# 账号学习进度同步

登录账号后，四六级 / 新概念卡片、难点本及复习评分、雅思高频词掌握 / 错词、阅读同义替换、听写 / 单词练习 / 新概念跟读的位置与输入、学习历史、听力时长和个人复习参数，使用统一的增量同步接口。个人录音和教材音频缓存不进入此接口。

## 使用和冲突处理

- 修改先写本机 IndexedDB，再于约 1.2 秒后提交；页面打开期间每 10 秒检查云端，回到前台和恢复网络时也检查。
- 状态入口显示待同步、同步中、已同步、离线或失败，并提供手动重试。新设备必须登录同一账号；访客记录不会自动归入登录账号。
- 账号切换前保存旧账号快照，再恢复新账号的本机缓存和云端记录。旧的互踢单设备限制不再启用。
- 服务端核验登录令牌并从验证结果确定账号，拒绝客户端指定账号。各账号的记录、版本和操作标识独立。
- 同一条记录采用版本校验；发生并发冲突时，比较记录修改时间，较新的整条记录保留。不同卡片 / 错词 / 日志分别同步，删除使用持久墓碑。同一张卡片同时复习不会合并成两次评分；设备时间明显不准时应先校准。
- 正在输入的练习不会被远程结果强行刷新；出现另一设备更新提示后，点击继续最新进度读取保存位置。关闭页面前可确认状态为“学习进度已同步”。
- 老版本卡片和难点本云记录仅在账号首次迁移、且统一云端为空时读取；本机已有的各模块记录也会迁移。尚未打开新版的设备，其旧本机记录要在该设备打开新版并登录后才会上传。
- 个人录音仍只保存在创建它的浏览器。更换设备、清理浏览器数据不会由云端恢复录音。

## 服务部署和备份

前端构建：`pnpm build`。同步服务：`scripts/deploy-sync.ps1`；前端：`scripts/deploy.ps1 -SkipBuild -FrontendOnly`。

`server/learning_sync.py` 使用 Python 标准库，systemd 服务 `listening-sync.service` 以 www-data 运行，监听 127.0.0.1:3197，由 nginx 精确代理 `/api/learning-sync`。认证配置在 `/etc/listening-sync.env`，只需要 Supabase 项目公开 URL 和 anon key，用户登录令牌逐请求核验；不需要 service-role 密钥。

学习记录保存在服务器私有目录 `/var/lib/listening-sync/progress.sqlite`，不在静态网站目录中。目录 0700，数据库 0600。接口不记录令牌、请求体或个人学习内容。

`listening-sync-backup.timer` 每天 03:15 触发 Python SQLite 一致性备份，备份位置 `/var/backups/listening-sync/progress-*.sqlite`，同样不公开。操作员应定期检查 timer 和备份磁盘占用；当前未配置异地备份或自动清理策略。数据库回滚需同时处理客户端游标，不能直接将旧备份覆盖在线数据库后继续运行。

检查服务：`systemctl status listening-sync.service listening-sync-backup.timer`。未登录 POST 接口应为 401。浏览器界面可检查最近同步时间和待传数量。

## 验证

`pnpm test` 包括两个隔离设备的增量往返、账号隔离、删除、断线重试、请求期间本地修改、日期序列化与安全白名单；`python -m unittest discover -s server -p "test_*.py"` 验证服务端认证、隔离、冲突、分页和幂等重试。自动化双设备测试不代表已在每一款手机实机上测试。

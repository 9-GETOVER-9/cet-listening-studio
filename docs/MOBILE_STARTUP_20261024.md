# 手机首次加载优化 · 2026-10-24

用户要求缩短手机首次打开的等待，参考 GitHub 原项目，并发布网站。沿用未合并的 `feature/ui-fluidity-20261024`，基线 `f26c4a7`；教材内容、音频和同步协议不迁移。

## 瓶颈与修改

- 登录启动原先等待完整云同步结束后才设置账号 ready；单次请求超时为25秒，且可能多轮交换。改为完成本地所有权隔离、旧账号快照与新账号缓存恢复后开放页面，云同步继续使用既有冲突处理、错误提示与重试。切换账号仍等待在途同步，不能显示旧账号投影。
- 首次加载已有轻量课程目录，但首页和雅思也要等待目录入库。它们现在可以先显示；其他需要目录的直接入口保留准备流程。先登记可等待的完整导入 promise，再显示学习链接，快速跳转到课程时仍能等待材料到齐。
- 当前 URL 的页面模块在启动时预加载，与会话和本地读取并行；并发预加载去重，失败后允许实际渲染时重试。完整卡片下载等待页面模块和课程索引准备，既有合并卡保护与进度不变。
- 新手引导改为独立懒加载，其动画库退出首屏必需依赖；引导模块离线不可用时不会使主应用空白。
- PWA 注册等到首个页面可以绘制后启动。预缓存只含应用壳及其静态依赖，功能模块在访问时缓存；排除宣传页面。实查旧生产清单引用了5个不存在的 `promo/*` 文件，会导致安装失败。已访问页面离线重开通过。

## 性能证据

为避免把公网与本地差异当成代码收益，从生产入口与当前预缓存清单提取旧版前端，在同一台机器以相同 gzip HTTP 服务交替运行旧版/新版，各三次。每次启动新的隔离浏览器，无真实账号、历史缓存或学习记录；390×844，CDP限速1.6 Mbps、150ms延迟、CPU 4倍降速。指标为导航开始到 `main h1` 可见，表示首页主内容出现，不代表所有教材完成下载或引导已关闭。

| 指标 | 旧版 | 新版 |
| --- | --- | --- |
| 首页主内容出现，三次(ms) | 3854 / 3811 / 3807 | 3191 / 3094 / 3120 |
| 中位数 | 3811 ms | 3120 ms，减少18.1% |
| FCP中位数 | 2484 ms | 2260 ms |
| 主脚本未压缩体积 | 415623 B | 289303 B（约减少30%） |

首轮公网旧版另测6207ms，仅作为现场记录，不与本地新版直接计算提升比例。模拟结果不能承诺所有实体手机相同耗时。完整卡片JSON仍约32MB，后台导入仍需要时间；本轮优先解除首屏阻塞，并未把教材重新分片。

诊断脚本与原始结果保存于被Git忽略的 `output/playwright/mobile-startup-20261024/`，包括 `paired-baseline-*`、`paired-final-*`、`baseline-slow-index.json`、`optimized-slow-index.json` 和手机截图。测试阻塞目录请求时，旧版无法出现首页，新版首页及雅思导航可操作；放行目录后完整卡片下载开始。

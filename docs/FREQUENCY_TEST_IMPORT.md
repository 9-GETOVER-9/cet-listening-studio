# 个人高频测试记录导入

入口：`/ielts/listening?source=frequency` 的“我的测试记录”。导入只更新当前登录账号的高频听写状态。正确词跳过普通听写和专注练习，错误词汇总成跨单元、按词去重的复习和双语随身听列表。明确点击“重新测验所选内容”仍允许主动重测。

## 数据与账号边界

- 导入文件为私有 JSON：`{ version: "frequency-test-import-v1", email, id, rows: [{ word, passed }] }`。只支持单次测试的最终正确/错误判定；整理 Excel 时采用表格明确标记，不能按拼写重新推断。文件不进入 Git 或公开站点。
- 网页在预览和确认时均核对当前认证用户与文件邮箱。Supabase `auth.updateUser` 只写当前用户的 `user_metadata.frequency_import_v1`，不使用管理密钥，也不按邮箱修改他人记录。
- 云端仅保存初次导入种子：词库顺序摘要、压缩判定和补充词，限制为 3500 个 JSON 字符，避免膨胀认证令牌。不包含原始答案、Excel 行、邮箱或录音。它是学习数据，不得作为权限依据。
- 新设备获取最新账号资料，校验词库摘要和总数，再以账号为键原子写入本地 Dexie。写入前留存账号进度备份；同一导入标识只执行一次，失败事务整体回滚。更新后的复习判定不会被再次加载旧导入覆盖。
- 同一导入中的重复词跨单元投影最新本地判定。未导入用户保持原有选择行为。当前版本没有增加后续复习结果的跨设备持续同步，UI 如实说明这一点。
- 用户通过“我的”明确确认清除学习数据时，同步清除云端导入种子；不会因再次登录而恢复已清除的种子。本轮不实际执行清除用户数据。

## 音频依赖与发布

优先使用原有高频/王陆中英索引中的精确同形词，不把复数或英美拼写强行映射到别的词形。缺失音频使用 Windows Zira/Huihui 离线合成，并标注“系统合成朗读”。公开补充词典只含通用词义及音频位置，不含用户、测试判定或来源表格。

补充资料独立维护（与原有公开语料相同，不进源码仓库）：

- `public/data/word-audio-supplement-v1.json`
- `public/data/audio/word-supplement/*.mp3`

发布前先上传并核验补充音频，再按前端发布流程选择性包含该新 JSON；不要替换原有语料、音频或客户记录。备份采用现有发布脚本。源码基于当前线上维护基线，原应用目录的其他未提交工作不参与发布。

## 验证

`frequencyImport.test.ts` 覆盖编码校验、同形词去重、账号隔离、错误回滚、重复导入、后续复习保持、新设备重建及专注练习跳过已掌握词。另用本地私有测试核验实际导入总数和全部错词的中英音频覆盖；该测试和表格不提交。

执行项目 `pnpm test`、`pnpm lint`、`pnpm build`。部署后通过已登录网页的正常文件选择与确认流程导入，并核对全量错词数、刷新保持和实际音频播放。
